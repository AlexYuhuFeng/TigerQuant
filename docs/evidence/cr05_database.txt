2. Per-mode isolation is enforced by the SERVER, not by convention
===========================================================================
Init script: deploy/postgres-init/01-databases.sql

$ psql -c "SELECT datname FROM pg_database WHERE datname LIKE 'tq_%'"
tq_backtest
tq_live
tq_paper
tq_shadow

$ psql -c "SELECT rolname, rolsuper, rolcreatedb, rolcreaterole FROM pg_roles WHERE rolname LIKE 'tq_%'"
tq_backtest  f  f  f
tq_live      f  f  f
tq_paper     f  f  f
tq_shadow    f  f  f
tq_bootstrap t  t  t     (administrative only; never used by the application)

$ psql -c "SELECT datname, datacl FROM pg_database WHERE datname LIKE 'tq_%'"
tq_backtest  tq_backtest=CTc/tq_backtest tq_bootstrap=c/tq_backtest
tq_live      tq_live=CTc/tq_live         tq_bootstrap=c/tq_live
tq_paper     tq_paper=CTc/tq_paper       tq_bootstrap=c/tq_paper
tq_shadow    tq_shadow=CTc/tq_shadow     tq_bootstrap=c/tq_shadow

There is no PUBLIC entry in any ACL, i.e. the implicit world-connectable grant was revoked
on template1 *before* the databases were created, so a new database is never briefly
exposed. The proof that this is a real partition and not a naming convention:

$ psql -U tq_backtest -d tq_paper -c "SELECT 1"
psql: error: connection to server ... failed: FATAL:  permission denied for database "tq_paper"
DETAIL:  User does not have CONNECT privilege.

The application role for one mode cannot open another mode's database at all. This is
AGENTS.md invariant 2 enforced by the database rather than by a namespace prefix.

Implementation note: `CREATE DATABASE` cannot run inside a transaction or a PL/pgSQL
function. The first version of the init script used a `DO $$ ... $$` loop and failed with
"CREATE DATABASE cannot be executed from a function", rolling back the role creation with
it. The script now uses `\gexec`, which executes each row as a standalone statement.

5. Defects found by running against a real server
===========================================================================
Each of these was invisible to the in-memory implementation and is now covered by a test:

1. **The lease deadlocked instead of refusing.** `PostgresLease.acquire` left its statement
   uncommitted, so a second acquirer blocked on the row lock rather than being told the
   lease was taken — the opposite of mutual exclusion. Lease operations now commit
   immediately, because a lease held inside an uncommitted transaction is invisible to
   every other worker.
2. **Event idempotency raised instead of ignoring.** `ON CONFLICT (event_id) DO NOTHING`
   only consults the named arbiter index, so a replay of the same event (same id *and*
   same seq) raised a UniqueViolation on the primary key. The insert now uses an
   untargeted `DO NOTHING` and re-establishes the distinction explicitly: already-present
   id is idempotent, a sequence owned by a *different* event is a loud fork.
3. **psycopg 3 does not adapt `dict` to `jsonb`.** Payload, attributes and alert context
   are now wrapped explicitly rather than relying on implicit adaptation.
4. **`events()` reconstructed events without their envelope**, so reading back a stored
   event failed validation. The query now selects the envelope columns and the repository
   stamps the mode back on, because the database boundary *is* the mode.
